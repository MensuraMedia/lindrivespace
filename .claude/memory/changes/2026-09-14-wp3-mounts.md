# Change: WP3 — mount & disk topology engine (M2 core half)

**Date:** 2026-09-14
**Work package:** WP3
**Type:** feature

## Summary
Pure-Python mount/disk discovery engine: merges `psutil.disk_partitions(all=True)`,
`/proc/self/mountinfo` and `lsblk -J -b` by major:minor (falling back to mountpoint), computes
per-mount usage via `os.statvfs`, groups mounts under their top-level physical disk (walking
through LUKS/LVM/partition layers), and a lazily-imported `pyudev` hotplug monitor exposing a
single non-blocking fd for the UI's `GLib.io_add_watch`. No GTK/cairo imports; `pyudev` is
imported only inside `MountMonitor.start()`.

## Design notes / contract concerns

- **Dataclasses**: `MountInfoRaw`, `LsblkNode`, `MountInfo` (all `slots=True, frozen=True`) and
  `DiskInfo` (`slots=True`, mutable — `mounts` list is built incrementally by `group_by_disk`).
  Field set matches the WP3 spec exactly.
- **Merge key ambiguity**: maj:min alone is *not* unique when a device is bind-mounted at more
  than one place (our LVM `/home` fixture is bind-mounted again at `/mnt/homebind`, both
  `259:3`). `list_mounts` therefore keys on `(maj_min, mountpoint)` first, falls back to
  `mountpoint` alone, then to `maj_min` alone — satisfying "merge by maj:min, fall back to
  mountpoint" while still picking the *correct* mountinfo row per psutil partition. This is a
  refinement of the literal spec wording, not a contract change; flagging it in case the
  orchestrator wants the ambiguity called out explicitly in the technical design doc (§8).
- **`/dev/mapper/<name>` aliasing**: LVM/LUKS mounts appear in `psutil`/`mtab` as
  `/dev/mapper/vgdata-lvroot`, but `lsblk`'s real `KNAME` is `dm-1`. `list_mounts` falls back to
  a name-match against `LsblkNode.name` when the raw device-path segment isn't a known `kname`,
  and reports the *real* `kname` (`dm-1`) on `MountInfo`, not the mapper alias. Verified end to
  end by `test_list_mounts_lvm_mapper_device_resolves_to_real_kname_and_disk`.
- **`disk_kname` semantics**: `None` for loop devices and any mount with no block-device
  backing (tmpfs, proc, ...); for a `disk`-type node itself it resolves to its own kname
  (self-reference), which is what lets `group_by_disk` always resolve a group via the same
  `disk_kname`/lsblk-index path for both partitions and (hypothetically) a disk mounted
  directly.
- **`hidden`**: fstype-in-list, OR mountinfo's own fstype-in-list (covers a rare mtab/mountinfo
  disagreement on bind mounts), OR a squashfs loop under `/snap/`. Default `include_hidden`
  behaviour matches settings' `DEFAULTS["mounts"]["show_hidden"] = False`.
- **`group_by_disk` ordering**: kind priority `nvme(0) < ssd/hdd(1) < usb(2) < loop(3) <
  virtual(4)`, tie-broken by `kname`, deterministic for tests. Mounts with no backing block
  device at all (tmpfs, proc, sysfs when `include_hidden=True`) land in one `kind="virtual"`,
  `kname=""` bucket.
- **`MountMonitor`**: no threads/callbacks, matches the "UI watches the fd" contract. `start()`
  catches any exception from `pyudev` (missing binary caps, no netlink permission, etc.) and
  leaves `available=False` rather than raising — `poll()`/`stop()` are safe no-ops in that case.

## Fixtures
`tests/core/fixtures/lsblk.json` / `mountinfo.txt` are captured from this dev machine (NVMe
root/home + a SATA SSD `/mnt/data`), trimmed to two squashfs loops (representative, not all
ten), plus three hand-written cases layered on top for scenarios this machine doesn't have:
a USB stick (`sdb`, vfat, labelled `USBSTICK`), an LVM-over-LUKS chain (`sdc` → `sdc1`
`crypto_LUKS` → `dm-0` `crypt` → `dm-1` `lvm` `ext4` mounted at `/mnt/vault`), and a rotational
SATA HDD (`sdd`, for the `hdd` kind test) whose partition is mounted at `/mnt/My Backup` — used
in `mountinfo.txt` to exercise the `\040` octal-escape decode. A bind mount of `/home` onto
`/mnt/homebind` exercises `is_bind` and the maj:min-ambiguity merge fix above.
