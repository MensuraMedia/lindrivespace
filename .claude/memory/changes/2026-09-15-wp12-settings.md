# Change: WP12 — Settings page (Appearance, Scanning, Exclusions, Mounts, Explorer, About)

**Date:** 2026-09-15
**Work package:** WP12 (gtk-ui agent)
**Type:** feature

## Summary
Replaced the M0 Settings stub with the full preferences page from the concept
document §3.5: six `PrefGroup` cards (Appearance, Scanning defaults,
Exclusions, Mounts, Explorer, About) built from a new small `PrefRow`/
`PrefGroup` layout helper. Every control persists to `Settings` immediately
(`settings.set` + `settings.save()`) — there is no Apply button — and
`SettingsPage.reload_from_settings()` re-reads every control's state (wired
to `on_shown`, so a setting changed elsewhere, e.g. the Explorer toolbar's
"hidden files" toggle, is reflected here on return).

Also did the accessibility pass this WP owns: every interactive control gets
`get_accessible().set_name(...)` matching its row label, `PrefRow` wires
`Gtk.Label.set_mnemonic_widget` from the row label to its control, and a new
`tests/ui/test_contrast.py` computes WCAG 2.x contrast ratios for both theme
token sets.

## Files
- `src/lindrivespace/ui/pages/settings.py` — replaced the stub with `SettingsPage`.
- `src/lindrivespace/ui/widgets/settings_rows.py` — new: `PrefRow` (label + description
  left, control right, accessible name + mnemonic wiring) and `PrefGroup` (`card` +
  `section-title` wrapper for a vertical stack of rows).
- `tests/ui/test_settings_page.py` — new, 12 tests using the shared session `window` fixture.
- `tests/ui/test_contrast.py` — new, 10 tests (parametrized over both themes plus the
  two fg_dim/bg_surface_2 cases) implementing WCAG 2.x relative luminance/contrast
  ratio directly in the test file.
- `.claude/memory/changes/2026-09-15-wp12-settings.md` — this file.

Did not touch `ui/window.py`, `ui/pages/__init__.py`, `app.py`, `config/*`,
`data/css/app.css`, `core/*`, `models/*`, `services/*`, or any other page/widget —
only read `explorer.tree.restore_state()` (already public, WP8) and
`app.theme_loader.apply()` / `app.theme` (already public, app.py) defensively.

## Accessibility pass results

- Every `Gtk.Switch`, `Gtk.SpinButton`, `Gtk.ComboBoxText`, `Gtk.Entry`, and
  `Gtk.RadioButton` on the page has a non-empty accessible name (asserted by
  `test_every_switch_spin_combo_entry_has_an_accessible_name`, which walks the
  widget tree).
- `PrefRow` always calls `label_widget.set_mnemonic_widget(control)`.
- Every control is a standard GTK widget with `can-focus` true by default;
  packing order equals visual order, so Tab order matches the page top-to-bottom,
  left-to-right (label → control) within each row.

### `tests/ui/test_contrast.py` — WCAG 2.x results (relative luminance implemented in-file)

| Pair | Dark | Light | Threshold |
|---|---|---|---|
| fg on bg_canvas/bg_surface/bg_surface_2/bg_sunken/bg_deep | 6.96 / 9.95 / 11.07 / 13.21 / 14.32 | 11.37 / 12.63 / 11.88 / 10.30 / 10.51 | ≥ 4.5 — **all pass** |
| fg_muted on bg_surface/bg_surface_2 | 6.08 / 6.77 | 6.05 / 5.69 | ≥ 4.5 — **all pass** |
| #ffffff on accent (#e95420) | 3.65 | 3.65 | ≥ 3.0 (large/bold text only) — **passes, noted for large/bold use only** |
| fg_dim on bg_surface_2 | 3.34 — **passes** | **2.53 — fails** (< 3.0) | ≥ 3.0 |

`config/theme.py` is orchestrator-owned, so the failing light-theme pair is
**not** patched here. `test_fg_dim_on_surface_2_meets_large_text_aa_light` is
marked `@pytest.mark.xfail(strict=False, ...)` reporting the ratio and the
smallest fix found: darken `fg_dim` from `#9a9ea6` to **`#8c9098`** (same hue,
~9% darker), which measures ~3.01:1 against `bg_surface_2` (`#f8f8f6`).

## Open issues / follow-ups
- The light theme's `fg_dim` vs `bg_surface_2` contrast gap above (2.53:1 vs
  the 3.0 floor) — orchestrator can apply the suggested `#8c9098` when the
  v1.1 light CSS pass lands.
- "Reset column layout" intentionally calls `explorer.tree.restore_state()`
  (re-reads settings, applies order/widths/visibility/sort) rather than the
  existing `ExplorerTree.reset_columns()` helper, because the latter doesn't
  reset sort order and reads its "default hidden" set from `explorer_tree.py`
  constants rather than `config/settings.DEFAULTS`; both are defensive
  `getattr` calls either way, so nothing breaks if the Explorer page changes.
