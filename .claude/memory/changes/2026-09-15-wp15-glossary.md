# Change: WP15 — Glossary page (sidebar feature: Linux drives/space/filesystems, explained)

**Date:** 2026-09-15
**Work package:** WP15 (gtk-ui agent)
**Type:** feature

## Summary
Replaced the M0 Glossary stub with a searchable, browsable glossary of Linux
disk, partition, filesystem, mounting, space-accounting, directory-tree,
storage-subsystem, and best-practices terms, per the user's request ("add a
glossary feature in the sidebar... explain in brief descriptions everything
there is to know about linux drive and space management, mountpoints,
directories vs folders, best practices, ext standards, etc.").

Content lives in a new pure-Python `core/glossary.py` module (no GTK, passes
`test_purity.py` and `mypy --strict`): a frozen `Term` dataclass, a 7-category
`CATEGORIES` tuple in display order, a 120-entry `TERMS` tuple, and
`by_category()` / `search()` / `get()` helpers. `search()` ranks title
matches first (in `TERMS` order), then summary/body matches — this is what
makes `search("ext4")` return the `ext4` term first even though other terms'
bodies mention "ext4" too.

`ui/pages/glossary.py` (`GlossaryPage`, already registered with
`scrolled=False` in the shared `ui/pages/__init__.py`, so it owns its own
`Gtk.ScrolledWindow`) is: a `Gtk.SearchEntry`, a linked row of category
`Gtk.ToggleButton` chips (All + one per category, single-selection enforced
manually — re-clicking the active chip or another chip never leaves zero
selected), a mono/dim "N terms" count label, and a `Gtk.ScrolledWindow` over
a `Gtk.ListBox` (`card` CSS class) of rows. Each row is rebuilt from
`glossary.search()`/`by_category()`/`TERMS` on every filter change (not a
`Gtk.ListBox` filter-func) specifically so that a search re-*orders* rows to
match `core.glossary.search()`'s title-first ranking, not just hides
non-matches in original `TERMS` order — needed for the "filtering by
'mountpoint' puts the mountpoint term first" requirement, since the `mount`
term's body also contains the word "mountpoint" and sits earlier in `TERMS`.

Activating a row (click, or Enter in the search box for the first visible
match) toggles a `Gtk.Revealer` holding the full body text and, when present,
"See also" flat-button links to related terms (`term.related`) that call
`show_term()`. Only one row is expanded at a time. Escape in the search box
clears it.

| Category | id | Count | Highlights |
|---|---|---|---|
| Disks & Partitions | `disks` | 13 | block device, MBR vs GPT, device names (sda1/nvme0n1p2/mmcblk0p1/dm-0/loop0), TRIM, wear levelling, SMART, udev hot-plug |
| Filesystems | `filesystems` | 24 | what "ext" means, ext2 vs ext3 (journaling) vs ext4 (extents/delayed alloc/1 EiB/16 TiB), XFS, Btrfs, ZFS, F2FS, vfat/exFAT/NTFS, squashfs, tmpfs, overlayfs, FUSE, inode, superblock, block size, 5% root reserve, fsck, mkfs, label, UUID, fstab |
| Mounting | `mounting` | 16 | mount/mountpoint/unmount, mount options, bind mounts, automount, mountinfo, findmnt/lsblk/df/du/ncdu, systemd mount units, removable media, NFS/SMB/sshfs, loop mounts |
| Space & Sizes | `space` | 17 | apparent vs allocated, sparse files, hard vs symbolic links, reflinks, GB vs GiB, reserved blocks, deleted-but-open files, trash, log/cache growth, swap, hibernation |
| Directories & the Tree | `directories` | 18 | directory vs folder, FHS overview + `/`, `/home`, `/etc`, `/var`, `/tmp` (sticky bit), `/boot`, `/proc`, `/sys`, `/dev`, dotfiles, permissions/ownership, absolute vs relative paths |
| Storage Subsystems | `subsystems` | 17 | VFS, page cache, block layer, I/O schedulers, device mapper, LVM, LUKS/dm-crypt, mdadm RAID, udev/polkit, io_uring, NVMe queues, SATA/AHCI, USB Mass Storage/UAS, SCSI, MMC/SD |
| Best Practices | `practices` | 15 | keep 10–15% free, separate /home, back up before resizing, snapshots, safe cache cleaning, never touch /proc·/sys·/dev, Trash not rm, `df -h`/`du -sh` first, weekly fstrim, SMART monitoring, GPT for new disks, noatime, never fill `/`, where LinDriveSpace's own numbers come from |

Every `related` cross-reference resolves to a real key (verified by a test);
a handful of `related` entries that would have pointed at individually-named
FHS directories I decided not to spin out as separate terms (`/opt`, `/srv`,
`/run`, `/snap`, `/mnt`, `/media`, `lost+found`) point at the `fhs` overview
term instead, which covers all of them in one place.
