# Change: WP17 — History page (drops Snapshots, adds automatic trend history)

**Date:** 2026-09-15
**Work package:** WP17 (gtk-ui agent)
**Type:** feature (replaces a prior feature)

## Summary
User request: rename the sidebar's "Snapshots" entry to "History", drop the
old save/diff-scans feature entirely, and replace it with automatic
historical disk-usage trending — a chart the user can switch between
Day/Week/Month/Year/All, plus a "Pattern History" section to save named
bookmarks of a particular path/period view.

A new pure-Python module, `core/history.py`, is the data layer: `Sample`
(one usage or scan reading), `Pattern` (a saved named view), and
`HistoryStore` (load/save JSON at `<cache_dir>/history.json`, `add_sample`
with a 1-hour/1%-change de-dupe rule for periodic "usage" samples while
"scan" samples are always kept, `paths()`/`samples()`/`series()`/`buckets()`/
`trend()` roll-ups per period, and `add_pattern`/`remove_pattern`/
`rename_pattern`). `core/` stays a leaf package: `default_history_path()`
replicates the XDG cache lookup from `config/settings.py` rather than
importing it, mirroring `core/snapshot.py::default_snapshot_dir`'s existing
precedent.

`ui/widgets/trend_chart.py` is a new themed `Gtk.DrawingArea`
(`TrendChart`, same Cairo/PangoCairo approach as `age_view.py`/
`treemap_view.py`): grid + y-axis byte labels, an accent area/line chart,
a warn-coloured dashed line at the filesystem total, aubergine ticks at scan
timestamps, an emphasised last point, a period-aware x-axis (hours for Day,
weekday for Week, dates for Month/Year/All) with greedy label placement so
labels never overlap regardless of point density, hover tooltips, and a
centred empty-state message.

`ui/pages/snapshots.py` had its entire content replaced with
`HistoryPage(BasePage)` (the old `SnapshotsPage` save/open/delete/diff UI is
gone — the feature is dropped per the user's request). The module keeps the
file/page-id name (`ui/pages/__init__.py`'s registry entry is
`PageSpec("snapshots", "History", ...)`, orchestrator-owned) and exports
`SnapshotsPage = HistoryPage` as a thin alias at the bottom for anything
still importing the old name. The page reads `self.app.history` (falls back
to a fresh `HistoryStore()` if the attribute is missing) and, when present,
connects to `self.app.history_signal`'s `"changed"` signal (both already
wired by the orchestrator in `app.py` — `LinDriveSpaceApp.history`/
`.history_signal`/`record_usage_samples`/`record_scan_sample`) to refresh
automatically as new samples are recorded.

Layout: a controls row (mount/path `Gtk.ComboBoxText` — mountpoints via
`os.path.ismount` sorted first, then other sampled paths; linked period
ToggleButtons Day/Week/Month/Year/All, single-selection, remembered in
`settings["history.period"]`; a "Save to Pattern History" button); a `Trend`
`PrefGroup` card (`enable_copy()`) holding the `TrendChart` plus a hidden
text-summary label so the card's Copy button carries real numbers; a 4-tile
stats row reusing `ui/widgets/kpi_tile.py`'s `KpiTile` (First, Latest,
Change — signed and coloured ok/danger via a small scoped `Gtk.CssProvider`
on that one label, same technique as `settings.py`'s
`_style_danger_label`, no hex literals — and Growth/day with a "full in ≈ N
days" detail line when the trend is growing and the total is known); and a
`Pattern History` `PrefGroup` with a `Gtk.ListBox` of saved patterns (name,
mono dim "path · period · saved <date>", first→last summary, Open/Remove),
an inline name-entry + Save/Cancel row (no modal dialog, shown by the
controls row's Save button) and an empty-state label.

## Files
- `src/lindrivespace/core/history.py` — new. `Sample`, `Pattern`, `PERIODS`,
  `default_history_path()`, `HistoryStore` (see contract above). Stdlib
  only; passes `mypy --strict` and `tests/core/test_purity.py`.
- `src/lindrivespace/ui/widgets/trend_chart.py` — new. `TrendChart(Gtk.DrawingArea)`.
- `src/lindrivespace/ui/pages/snapshots.py` — replaced. `HistoryPage(BasePage)`
  + `SnapshotsPage = HistoryPage` alias. Old snapshot save/compare code
  (`core.snapshot` usage, `list_store`/`diff_store` TreeViews) removed.
- `tests/core/test_history.py` — new, 26 tests: usage-sample interval + 1 %
  de-dupe rule (skip/keep/interval-elapsed), scan samples always kept,
  trimming to `max_per_path`, `paths()` most-sampled-first ordering, `series()`
  period filtering + unknown-period `ValueError`, `buckets()` per period
  (hourly/6-hourly/daily/weekly/~monthly, last-sample-wins, empty when no
  data), `trend()` (empty/growing/flat/shrinking/unknown-total cases for
  `per_day` and `days_to_full`), pattern add/remove/rename (+ no-op rename of
  a missing id), corrupt-file → `.bak` + empty store, and an atomic
  save/reload round trip.
- `tests/ui/test_history_page.py` — new, 16 tests using the shared session
  `window` fixture (`tests/ui/conftest.py`), a fresh `HistoryStore` injected
  per test (`page.store = HistoryStore(tmp_path/"history.json", ...)`):
  combo lists the seeded path, default period is Week, switching periods
  changes the chart's point count, stats labels non-empty (and show the "—"
  placeholder with no selected path), `save_current_view`/Open/Remove on
  Pattern History rows, and `TrendChart` renders a non-empty pixbuf in a
  `Gtk.OffscreenWindow` both with data and in the empty state (the render
  helper carefully detaches/reattaches the chart from its live parent so
  later tests in the same session still see an intact page).
- `tests/ui/test_snapshots.py` — **removed**. It exercised only the dropped
  Snapshots feature's API (`save_current`, `list_store`, `combo_a`/`combo_b`,
  `diff_store`, `delete`), none of which exists on `HistoryPage`; kept
  obsolete it would fail on every collection of `tests/ui`.

Screenshot: seeded a `HistoryStore` with ~60 usage/scan samples over 3 months
for "/" and "/home", showed the History page on Month, via a throwaway
script (`Gdk.pixbuf_get_from_window`, same as `app.py --screenshot`) in the
session scratchpad. Found and fixed a real bug this way: the x-axis date
labels overlapped/duplicated at higher point densities (the original
index-stepping math under-counted the step via floor division, so a "cap at
15 labels" budget could still emit 20+). Replaced with a greedy left-to-right
placement in `TrendChart._draw_x_labels` that only draws a label once there
is real horizontal room since the last one — verified overlap-free at Day/
Week/Month/Year/All. Confirmed separately (by rendering the unmodified
Overview page through the same script) that the window growing somewhat past
1200×800 in this sandbox is a pre-existing Xvfb/WM sizing quirk affecting
every page equally, not something introduced here. Final layout: the chart
fills the full card width (GtkBox's cross-axis fill is independent of
`pack_start`'s along-axis expand/fill flags, so `PrefGroup.add_row` was fine
as-is), stats tiles and Pattern History rows are compact and legible, and
the whole page fits without a horizontal scrollbar.

## Notes for the orchestrator

- Nothing else in `src/` referenced the old `SnapshotsPage` API
  (`save_current`, `list_store`, etc.) — grepped for
  `pages["snapshots"]`/`pages.get("snapshots")`/`save_current` and found
  no callers outside the old page itself.

## Open items / follow-ups
- `TrendChart`'s y-axis scale always includes the filesystem `total` when
  known, so a nearly-empty, nearly-full filesystem's small trend can look
  visually flat against a tall scale — acceptable given the dashed total
  line is exactly the point of reference the WP asked for, but a future
  "zoom to data range" toggle could help very small folders/mounts.
- Pattern History rows don't currently support rename from the UI (the core
  API `HistoryStore.rename_pattern` exists and is unit-tested, but no widget
  calls it yet) — left out as out-of-scope for this request, which asked
  only for save/open/remove.
