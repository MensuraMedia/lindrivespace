# Change: WP16 — Hardware page (System, board, CPU/memory, storage controllers, disks, live I/O)

**Date:** 2026-09-15
**Work package:** WP16 (gtk-ui agent)
**Type:** feature

## Summary
Replaced the M0 Hardware stub with a full page reporting what the kernel
knows about the local machine via unprivileged queries only (`/proc`, `/sys`,
`lsblk`, `lspci`, `lscpu`, `systemd-detect-virt`) — no `sudo`/`pkexec`, ever.
SMART data and similar root-gated fields are simply omitted, with a standing
note explaining why.

A new pure-Python collector, `core/hardware.py`, gathers everything into one
frozen `HardwareReport` dataclass tree (`SystemInfo`, `BoardInfo`, `CpuInfo`,
`MemoryInfo`, `StorageController`, `DiskHardware`, `IoStats`/`IoRate`) via
`collect(sys_root="/sys", proc_root="/proc")`. Every sub-collector reads from
an injectable root or injectable text so it is unit-testable against canned
fixtures without touching the real machine, and `collect()` wraps each
collector in its own `try/except` so one failed source (e.g. `lspci` missing)
becomes a note in `HardwareReport.notes` instead of aborting the report or
raising — verified with `sys_root`/`proc_root` pointed at a nonexistent path.

`HardwarePage` (`ui/pages/hardware.py`) runs `hardware.collect()` on a
background `threading.Thread` on first show, delivering the report back to
the main thread via `GLib.idle_add` (the same one-shot worker-thread shape
`services/mounts_service.py` uses for the Overview page, kept local to this
page since WP16 owns only this file + `core/hardware.py`, not a new service).
A "Reading hardware…" spinner covers the gap. Eight `PrefGroup` cards follow
`ui/widgets/settings_rows.py`'s visual language (System, Motherboard &
firmware, Processor & memory, Storage controllers, Supported drive types as
`badge`-styled chips in a `Gtk.FlowBox`, Disks as a fixed-height
`Gtk.TreeView`, I/O activity as a second `Gtk.TreeView` refreshed every 2 s
via `GLib.timeout_add_seconds` while the page is visible — started in
`on_shown`, stopped in `on_hidden` — Filesystems supported, and dim Notes).
A toolbar has Refresh (re-runs collection) and Copy report (`core.hardware
.to_text` onto `Gtk.Clipboard`).

## What this machine (AZW SER mini-pc, AMD Ryzen 5 5560U) reported
- System: Linux Mint 22.3, kernel 7.0.0-28-generic, x86_64, chassis "mini-pc",
  virtualization "none".
- Board: AZW / SER / V1.0, BIOS American Megatrends International FP655U509
  (12/12/2023).
- CPU: AMD Ryzen 5 5560U, 1 socket, 6 cores, 12 threads, ~4063 MHz max,
  notable flags aes/avx/avx2/sse4_1/sse4_2/sha_ni/svm. 13.5 GB RAM, no swap.
- Storage controllers (lspci): NVMe (Sandisk/WD Black SN770), 2×USB 3.1
  (AMD Renoir/Cezanne), SATA/AHCI (AMD FCH).
- Disks: `/dev/sda` Samsung SSD 870 EVO 1TB (SATA SSD, mq-deadline, TRIM yes,
  1 partition) and `/dev/nvme0n1` WD_BLACK SN770 2TB (NVMe SSD, scheduler
  "none", link "8.0 GT/s PCIe x4", firmware 731100WD, TRIM yes, 3 partitions).
- Supported drive types: NVMe, SATA/AHCI, USB mass storage.
- Filesystems: ext3/ext2/ext4/squashfs/vfat/fuseblk/btrfs/zfs (+ pseudo:
  sysfs/tmpfs/proc/cgroup/... /autofs/binfmt_misc).
- Notes: standing note that SMART, full serials and some sensors need root
  and are never requested.

## Bugs caught along the way
- The active-scheduler regex (`\[(\w+)\]`) missed hyphenated scheduler names
  like `mq-deadline` (`\w` excludes `-`) — both this machine's disks use it,
  so the real-machine `collect()` smoke check caught it immediately. Fixed to
  `\[([\w-]+)\]`; a fixture-backed regression test
  (`test_read_scheduler_handles_hyphenated_names`) covers it.
- `chassis_type_name("35")` → `"mini-pc"`; naively `.title()`-casing that for
  display produced "Mini Pc". Added a small UI-only display-label override
  table (`_CHASSIS_TYPE_LABELS` in `ui/pages/hardware.py`) rather than
  teaching `core/hardware.py` about display casing.

## Open items / follow-ups
- SATA link speed (`_sata_link_speed`) resolves the disk's ata_link via
  `os.path.realpath` on `/sys/block/<kname>/device`; this machine's SATA SSD
  reports no link speed this way (its ata_link topology didn't match the
  `linkN` pattern this helper looks for) — shows "—" rather than a wrong
  value, which is the intended safe fallback, but a machine with a cleaner
  ahci topology would be a better test of that path than this one.
- No new CSS was added — the "badge" class (already used for MountCard's
  primary/secondary role pill) was reused for the drive-type chips.
