# Change: WP5 — custom widgets (percent bar, ring gauge, mount card, KPI tile)

**Date:** 2026-09-14
**Work package:** WP5 (gtk-ui agent)
**Type:** feature

## Summary
Four theme-driven, Cairo-drawn widgets used by the Overview and Explorer pages (WP7/WP8 wire
them in): a `Gtk.CellRenderer` percent bar for the tree-table, a `Gtk.DrawingArea` ring gauge for
per-mount usage, a `Gtk.Frame` mount card that combines a ring with mount identity/usage/scan
controls, and a plain `Gtk.Box` KPI tile for the Overview header strip. Every widget takes a
`ThemeDefinition` and reads colours only through `theme.rgb(token)` / `theme.rgba(token, alpha)`;
all metrics come from `Layout.dimensions` (`ROW_HEIGHT`, `BAR_WIDTH/HEIGHT/RADIUS`, `RING_SIZE`,
`RING_STROKE`, `CARD_WIDTH/HEIGHT`, `KPI_HEIGHT`).

## Constructor signatures & signals (for WP7/WP8)

```python
PercentBarRenderer(theme: ThemeDefinition)
# GObject props: percent: float [0,100], text: str, emphasis: bool
# .set_theme(theme) — live theme swap, no recreation needed
# do_get_preferred_height always returns (ROW_HEIGHT, ROW_HEIGHT) — safe for
# Gtk.TreeView.set_fixed_height_mode(True)

RingGauge(theme: ThemeDefinition, size: int = RING_SIZE, stroke: int = RING_STROKE)
# GObject props: percent: float [0,100], label: str (empty -> f"{round(percent)}%")
# .set_percent(percent) — clamps 0-100 and queues a redraw
# .set_theme(theme)
# module-level colour_token_for_percent(percent) -> "accent" | "warn" | "danger"
#   (<85 accent, 85-94.99 warn, >=95 danger) — unit-tested directly, reusable elsewhere

MountCardData(name, device, fstype, mountpoint, used: int, total: int,
              scanned_at: str | None, kind: str)
# Local dataclass (no dependency on WP3's mount module by design — WP7 adapts its own
# mount objects into this). kind: "usb" -> media-removable-symbolic,
# "ssd"/"nvme" -> drive-harddisk-solidstate-symbolic, else drive-harddisk-symbolic.

MountCard(theme: ThemeDefinition, data: MountCardData)
# Signals: "scan-requested" (str mountpoint) — emitted by the Scan/Rescan button.
#          "selected" (str mountpoint) — emitted on button-press on the card body
#          (via an internal Gtk.EventBox; does not fire from clicking the Scan button).
# .set_selected(bool) — toggles "selected" CSS class on the frame and "primary" on the button.
# .update(data: MountCardData) — replaces data and refreshes every label/icon/ring.
# .set_theme(theme) — propagates to the internal RingGauge.
# Public attributes used by tests/WP7: .ring, .icon, .name_label, .device_label,
# .usage_label, .scanned_label, .scan_button.

KpiTile(theme: ThemeDefinition, label: str, value: str, unit: str = "", detail: str = "")
# .set_value(value, unit=None, detail=None) — unit/detail unchanged when omitted.
# Public attributes: .label_widget, .value_label, .unit_label, .detail_label.
# No custom Cairo drawing (plain CSS-styled Box: "card" + "section-title"/"kpi-value"/
# "muted"/"dim" classes from data/css/app.css) — theme kept only for API parity with
# the other three widgets.
```

## Decisions / notes
- `format_bytes` already existed in `src/lindrivespace/core/units.py` (pure stdlib, no GTK) —
  imported directly into `mount_card.py` rather than duplicating a local `_fmt`, per the
  "use the closest existing one" instruction.
- `PercentBarRenderer` centres the label over the full bar/track width (not just the filled
  portion), per the WP5 brief; this differs slightly from the Direction A mockup's screenshot
  where the number reads as right-aligned in the column — the brief's literal wording ("label
  centred over the bar") was treated as authoritative.
- `MountCard`'s "selected" signal is wired to a `button-press-event` on an internal
  `Gtk.EventBox` wrapping the card body (a `Gtk.Frame`/no-window widget can't receive button
  events directly). Clicking the Scan/Rescan button does not also fire "selected" — GTK delivers
  the event to the button's own window, not the eventbox.
- `RingGauge`/`PercentBarRenderer` import `cairo` directly (in addition to `gi.repository`) for
  `cairo.LINE_CAP_ROUND` — allowed under `.claude/rules/python-gtk.md` ("Custom drawing goes
  through `Gtk.CellRenderer` / `Gtk.DrawingArea` with Cairo"); this only applies to `ui/`, not
  `core/` (which must stay GTK/Cairo-free per `core-purity.md`).
- `MountCard`'s usage line (`set_line_wrap(True)`) can wrap to two lines for long values (e.g.
  "... free of 1.70 TB"), growing the card past `CARD_HEIGHT` — matches the brief ("Size request
  CARD_WIDTH x CARD_HEIGHT (**may grow**)").

## Test approach
`tests/ui/test_widgets.py` places each widget in a `Gtk.OffscreenWindow`, pumps
`Gtk.main_iteration_do(False)` while events are pending, and asserts `get_pixbuf()` is non-empty.
- `PercentBarRenderer` is exercised inside a real `Gtk.TreeView`/`Gtk.ListStore` (headers hidden
  so row 0 sits flush with the pixbuf's top edge); at 100% the pixel sampled a few px inside the
  fill's left edge (clear of the centred label glyphs and the rounded-corner anti-aliasing) is
  asserted within ±8 per channel of `#e95420`.
- `RingGauge`: `colour_token_for_percent` boundary-tested directly (84.9/85/94.9/95/100), plus
  `set_percent` clamping (150 -> 100, -20 -> 0) and a render smoke test.
- `MountCard`: `scan-requested` fires with the mountpoint on `scan_button.clicked()`;
  `set_selected` toggles both the frame's "selected" class and the button's "primary" class;
  `update()` refreshes the Scan/Rescan label and the scanned/not-scanned text.
- `MountCard`/`KpiTile`/`RingGauge` render tests deliberately do **not** call
  `OffscreenWindow.destroy()` in the shared `_render()` helper — destroying the window also
  destroys its child widgets, which broke a first draft of the scan-button-click test (`clicked()`
  on an already-destroyed button is a silent no-op).
