# Change: WP2 — scanner engine, units, CLI helper

**Date:** 2026-09-14
**Work package:** WP2
**Type:** feature

## Summary
Headless scan engine: iterative-DFS `Scanner` over `core/fsnode.FsNode`, emitting the
pre-order `DirStarted` / post-order `DirDone` events from `core/events.py` (per the §16
errata, not §5.1's original post-order-only design), plus `Progress`/`Finished`/`ScanError`.
A background-thread wrapper (`ScanThread`), a stdlib-only formatting module (`core/units.py`),
and the `pkexec`-launched CLI helper (`core/scanner_cli.py`).

## Design decisions
- **DirStarted never carries DENIED/error flags.** Denial/OSError on `os.scandir()` can only
  be known *after* the open is attempted, which happens after `DirStarted` is already emitted
  pre-order for that directory. `DENIED` (and `PARTIAL` on cancel) show up only on `DirDone`
  and on the final `FsNode.flags`. `MOUNTPOINT`/`EXCLUDED` are known before opening, so those
  *do* appear on `DirStarted` as well as `DirDone`.
- **Symlinks are never `FsNode`s.** `entry.is_dir(follow_symlinks=False)` is `False` for a
  symlink regardless of what it points to, so a symlink (including a directory symlink,
  e.g. a loop) is always routed to the file branch: counted via `node.add_file()` using its
  own `lstat` size/alloc, never descended. This is what makes symlink loops terminate for
  free, with no explicit loop/visited-set bookkeeping needed.
- **Mount-boundary/exclusion checks use `entry.path`**, not `FsNode.path()` — `entry.path` is
  already the absolute path scandir builds internally, so no per-entry path-join/walk-to-root
  cost is added to the hot loop.
- **`os.scandir()`'s return type has no public typeshed name** (`os._ScandirIterator[str]`);
  the alias lives under `if TYPE_CHECKING:` only. It must not be evaluated at import time —
  an earlier draft defined it at module scope and broke both `test_purity.py` (subprocess
  import) and the CLI run before I caught it via `from __future__ import annotations` deferring
  every *annotation*, but not a top-level assignment statement.
- **Cancellation is checked every loop iteration**, not throttled to "every 1000 entries" as a
  literal reading of the spec might suggest — `Event.is_set()` is cheap, and checking on a
  1000-entry modulo does not actually guarantee "at least once per directory" for small
  directories (a `continue` on dir-open/dir-close doesn't advance the entry counter). Checking
  unconditionally trivially satisfies both stated minimums at negligible cost.
- **`scanner_cli.py`'s `sys.path` bootstrap** inserts `parents[2]` of the file (three ancestors
  up: `core/` → `lindrivespace/` → `src/`), guarded by `if __package__ in (None, "")`, so it only
  activates when run as a bare script. Verified both as `python -m lindrivespace.core.scanner_cli`
  and as `python /abs/path/scanner_cli.py` with `PYTHONPATH` unset and a fully stripped `env -i`
  environment (simulating `pkexec`).
- **SIGINT → cancel, not exception.** `scanner_cli.main()` installs a `SIGINT` handler that
  sets the same `threading.Event` the scanner's own cooperative-cancel path polls, so a Ctrl-C
  still gets a proper `Finished(cancelled=True)` (with `PARTIAL` flags) through the normal
  cancel machinery rather than an abrupt traceback; exit code is 130 either way.
- **`--top-files N` / other CLI flags map straight onto `ScanOptions`**; `--exclude PATH` is
  repeatable and *replaces* `DEFAULT_EXCLUDES` when given (documented in `--help`), since the
  common use is "scan just this subtree, skip these few paths" rather than appending to the
  system-wide default list.

## Contract concerns for the orchestrator
None — no changes needed to `core/{fsnode,events,options}.py`. Everything WP2 needed (flag
bits, event fields, `is_excluded`) was already present.

One near-miss worth recording: `ScanOptions.show_hidden` **defaults to `True`**, i.e. hidden
files/dirs are shown unless a caller opts out — the opposite of what I first assumed from the
work order's phrasing ("Hidden files: `show_hidden=False` skips..."). No code change was
needed since the scanner just reads the flag, but it cost a debugging round on
`test_totals_match_independent_walk` (my independent-reference walker unconditionally skipped
dotfiles, which disagreed with the scanner's own, correct, default-True behavior once I
actually read `options.py`). Flagging in case anyone else makes the same assumption.

## Testing notes
- `tests/core/test_scanner.py`'s `independent_walk_totals()` is a from-scratch recursive
  scandir walker (not adapted from `scanner.py`) used as the oracle for the totals-matching
  test, so it doesn't just assert the algorithm agrees with itself.
- Mount-boundary behavior is tested by monkeypatching `os.lstat` for the root path only (real
  bind mounts need root privileges the test sandbox doesn't have): this fakes the *root's*
  `st_dev` so every real child directory looks foreign relative to it, exercising the
  `MOUNTPOINT` / `cross_mounts` path end to end without a second filesystem. Monkeypatching
  `os.lstat` more broadly does **not** work for per-entry checks — `DirEntry.stat()` is a
  distinct C-level call that does not go through `os.lstat`.
- `denied`-directory fixtures are chmod 0 during the test and restored to 0o755 by a fixture
  finalizer (`fixture_tree`), otherwise pytest's own `tmp_path` cleanup fails on later runs
  with "Directory not empty" trying to remove an unreadable dir.
- `os.geteuid() == 0` skips the one test that depends on permission enforcement (root bypasses
  chmod 000 entirely, confirmed empirically, not just per the work order's caveat).
