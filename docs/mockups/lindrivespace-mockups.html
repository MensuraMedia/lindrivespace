LinDriveSpace design directions

Four directions for the mount, partition, folder and file size explorer, plus the shared component sheet. All four sit on the gray‑temperature surfaces with Ubuntu type and a single Ubuntu‑orange accent; they differ in what the first screen is for and how dense it is. Sample figures come from this machine's real mount layout.

nvme0n1p2 ext4 / 100 GB nvme0n1p3 ext4 /home 1.7 TB nvme0n1p1 vfat /boot/efi 512 MB sda1 ext4 /mnt/data 931.5 GB 10 × squashfs snap loops (hidden)
Direction A

Classic Tree‑Table

Closest to the reference. The Explorer is the whole app: one dense tree‑table with size, allocated, files, folders, percent‑of‑parent bars and modified date, a breadcrumb strip above it and scan progress in the header. Mounts live on a secondary Overview page. Motivation: zero learning curve for TreeSize / WizTree users. Trade‑off: mount health is a page away, and the table is the only visual.

Direction B

Overview Dashboard

Mounts first, then drill in. The first screen is a summary: four KPI tiles, then every mount as a card grouped by physical disk with a usage ring, used/free, and a Scan button. Below, the last scans. The tree‑table from Direction A opens on Scan. Motivation: answers "which disk is full?" before any scan runs, and shows hot‑plugged USB drives as they arrive. Trade‑off: two clicks to the tree.

Direction C

Gray‑Temperature Cards

The UI‑kit reference, literally. Soft raised cards and sunken wells, a large dial for the selected mount, round mode buttons (allocated vs apparent, hidden files, follow links, cross mounts) and the tree in a recessed well. Motivation: strongest visual identity, matches the kit image. Trade‑off: neumorphic depth costs vertical space and has to be drawn with Cairo, so rows stay flat inside the well.

Direction D

Analyst Split

Tree plus insight panel. The tree‑table keeps the left 70 %; a docked panel on the right shows a squarified treemap of the selected row, the largest files inside it, and an age histogram of allocated bytes. Ubuntu Mono carries paths and raw byte values. Motivation: the treemap makes the 80/20 obvious at a glance and the top‑files list is where deletions actually happen. Trade‑off: the tree loses two columns of width at 1200 px; the panel collapses below 1100 px.
